# 批 I · 屏蔽的作用域（block scope）—— 需求档

> 本档只写**要解决什么**（三层：总体目标 / 功能用户故事 / 非功能标准）与**明确的非目标**。
> **怎么做**在设计档 [`docs/2026-10-12-block-scope-design.md`](2026-10-12-block-scope-design.md)。
> 行号一律 as-of **2026-10-12 工作树（commit `663a91f`）**，实施按**符号名**定位。★ 本档全文不写出框定 token 的原串（批 E 立的仓规）。

---

## 一、总体目标

把「屏蔽」的作用域从**部署级全局**改成**两个会话之间**（**双向**），并补上**解除出口**。

**一句话**：今天点一次【屏蔽】，等于把那个会话**在整个部署里拉黑**，而且**没有任何办法解除**；要改成「只挡我们两个之间，并且随时解得开」。

## 二、功能用户故事

| # | 故事 | 今天的行为（痛点） |
| --- | --- | --- |
| **US-I1** | 作为使用者，我屏蔽一个会话 ⇒ **只挡我们两个之间**的投递（**双向**），**不影响**它跟其它会话的正常往来 | 屏蔽只按 `sender.id` 一个键落盘（`lib/index.js:7800`），而策略是**一份部署级共享文件** ⇒ 别的会话读到同一份、按同一个键判断（`:7682`）⇒ **被屏蔽者对所有会话都发不出去**。真机 2026-10-12 15:17：`team-link-mal-analyze-1011-coordinator-2345e3ad` 被一枚屏蔽弄到「所有跨会话消息都发不出去」 |
| **US-I2** | 作为使用者，我要能**解除**某一对会话之间的屏蔽 | 代码里**没有任何解除路径**（全库 `blockedSenders` 只见默认值 / schema / 归一化 / 迁移拷贝，**无 filter、无删除动作**）⇒ 误点之后**只能手改 `policy.json` + 重启**（真机事实：2026-10-12 父侧就是这样救回来的） |
| **US-I3** | 作为被挡住的一方，我要能从**拒绝文案**里知道「**谁**挡的、**怎么解**」 | 今天的文案只说「目标会话已屏蔽来自当前会话的消息」（`:7691` / `:7804`）—— **不说是谁挡的、不说出口在哪** ⇒ 卡住的人只能猜 |
| **US-I4** | 作为使用者，**已存在的旧屏蔽记录**不能因为这次改动被**静默放开** | 旧记录只有「发送方」一个 key（无接收方）⇒ 改成配对后**无法直接换算**；若直接丢弃 = 静默解除保护（安全向的坏方向） |

## 三、非功能标准

| # | 标准 | 判据方向 |
| --- | --- | --- |
| **NF-I1** | **不误伤**：解除/新增某一对，**不影响**任何其它对、其它团队、`teams` / `watchdogs` / `pairs` / `trustedSenders` / `rememberTargets` | 盘上逐字段比对 |
| **NF-I2** | **双向**：A↔B 屏蔽后，**A→B 与 B→A 都拒** | 两条方向各一条判据 |
| **NF-I3** | **旧数据不静默放开**：旧格式条目**保留原保护**（退化为「对所有人」）并**明确标注**，附**可执行的解除指引** | 迁移判据 + 读面文案判据 |
| **NF-I4** | **可机械验证**：判据必须能红（屏蔽只挡那一对 / 解除真的解开 / 旧条目行为） | 红相夹具 + 负相自证 |
| **NF-I5** | **零新依赖**：不得新增 import（八模块白名单是硬闸门） | 静态扫描 `^import` 仍 8 条 |
| **NF-I6** | **落点不变**：仍单写 `policy.update`（`AGENTS.md` §七「一个时刻只写一处」） | 落点行三态不变 |

## 四、明确的非目标（本批不做）

1. **不动既有的双门批准**（gate 1 发送方批准 / gate 2 接收方批准）—— 批准与屏蔽是两回事，本批只动屏蔽；
2. **不改 roster / 团队 / 换届**；
3. **不做批量解除**（一次解一对）；
4. **不碰黑板文件**；
5. **不做「投递目标过期」**（往已换届的旧会话投递）—— 那是**路由**的账，另立待办（`docs/backlog.md` 的 **B-3**），不塞进本批；
6. **不做「屏蔽某个角色/团队」**（本批只认**会话与会话**，与 US-I1 的口径一致）。

**用户已确认的三点（2026-10-12 会话内）**：
① **双向**（A↔B 互相都发不了，不是单向）；② 解除出口 = **工具动作 + 拒绝文案里说清出口**（两样都做）；③ 旧的全屏蔽条目**保留原保护 + 明确标注**（**不静默放开**）。
