## 一、总体目标（一段话）

让插件的三类注册（**系统提示段 / 动态上下文 / 看门狗工作台**）具备**可预期的一生**：
该在的时候**自动在**（不靠人肉命令补挂）、不该被谁随手拿走的时候**拿不走**（全队资产不由单个会话一句话丢掉）、
以及在被证明代价可接受时**按需节流**。
**一句话**：把「注册」从事后补救的运维动作，变成插件自己保证的不变量。

## 三、明确的非目标（本批不做）

| # | 不做的事 | 为什么 |
| --- | --- | --- |
| NF-1 | **不新增用户可见动词**（例如 `disarm-team` 这类显式的「关掉某队自动摘要」） | 新增动词要自己的设计档与判据面；本批 D-2 只做**收窄**，不做**新出口** |
| NF-2 | **不改** attach 链本身（rearm / 段同步 / 按队补挂 的顺序与语义） | D-1 走**事件驱动自愈**，不重排既有时序 |
| NF-3 | **不改**看门狗的 TTL、去抖、阈值、投递条件 | 与本次缺陷无关 |
| NF-4 | **不把 D-3 当作必做**：它量级仅 0.02%，允许在本批内被判定为「不做」并如实登记 | 设计档 §9.2 要的是**评估**，不是既定动作 |
| NF-5 | **不碰** workbench digest 的**正文形态**与状态卡第 ⑧ 段。**豁免（评审 🔵#8 的界定）**：摘要末尾那条**投递脚注提示行**是 FR-2 的交付面，本批**要改** —— 「内容形态」不含它 | 与批 C 的 NF-2 同一纪律 |

## 四、验收面（用户可见）

1. 重启 DSH → 打开任一团队会话 → **它的第一步**就带角色文本（协调者宪章 / worker 义务行）；
   动作上下文（context 通道）在**该步或下一步**出现 `[team-link 会话资源]` 行。**全程不需要人肉跑任何命令。**
2. 在现任协调者会话里跑 `team_link_watch action=clear` → **auto 工作台注册仍在**（`watch list` 与 `policy.json` 双读数），并收到一句点明原因的回执。
3. 摘要脚注的文字与 `clear` 的真实作用域**逐字一致**（不再建议一件会坑掉全队的事）。
