## 1. 白话版

形态**不是功能开关，是通道选择**：

- **多会话档**（默认）：平级会话之间，靠本插件的**跨会话身份与信任层**（投递 / 配对 / 换届 / 黑板）。
- **agent-team 档**：一个会话**内部**的子代理团队（宿主 Agent Teams：Lead + teammate、任务板、邮箱）。

三句要紧的话：

1. **人说了算**：人在对话里说一声 → 模型发起 → **弹一次确认框** → 我点一下才落笔（并往 `decisions.md` 记一行）。
2. **切了就换通道，不换人**：**信任不自动迁移**（旧配对必须人重新批准）。
3. **宿主没开就报错指路，绝不悄悄退回多会话** —— 「悄悄降级」正是本仓最反对的那类事故。

本插件在 agent-team 档下**只做名册与指路**，**不代理**宿主的派活/任务板（那是宿主的属地）。

## 4. 方案

### 4.1 形态字段（只落在 settings）

`TeamConfig` 扩两字段：

| 字段 | 形状 | 说明 |
| --- | --- | --- |
| `mode` | `z.string().default("sessions")`，闭集 `sessions` / `agent-team` | **默认 `sessions`** ⇒ 既有团队零迁移 |
| `leadSessionId` | `z.string().default("")` | 仅 `agent-team` 档有意义；**指针，不是名册** |

`normalizeTeams` 的降级：读到**闭集外**的 `mode` ⇒ 落 `sessions` **并留痕**（沿用既有范式：不可读 ⇒ 降成可读状态）；`agent-team` 而 `leadSessionId` 为空 ⇒ 保留档位但读面标 `Lead 未知`（**不编造**）。

### 4.2 写路径：`team_link_roster` 加第五个动词 `set-mode`

**动词闭集从四值扩为五值**（`set-mode`），参数：

| 参数 | 语义 | 边界 |
| --- | --- | --- |
| `mode` | `sessions` / `agent-team` | 闭集外 ⇒ **拒绝并列出两个值** |
| `leadSessionId?` | agent-team 档的 Lead 会话 | **省略 ⇒ 默认取调用方自己的会话 id**（切换的人通常就是 Lead），并在确认框正文里**明示该默认值**（人可见即可否决）；**显式空串 ⇒ 拒绝**（agent-team 档没有 Lead 就没意义）；非空必须通过**两道校验**：① 形状 `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$`；② **在场校验** —— 能在本次会话列表快照里找到（防转录错位，沿用本仓既有教训） |

**宿主探测（只对「切**到** agent-team」这一向）**：切到 agent-team **之前**先探测宿主 Agent Teams 能力；探测不到 ⇒ **拒绝 + 指路（告诉人怎么开）+ 零写入**（US3）。切**回** sessions 档不需要探测（回默认档永远可用）。

**双重门（缺一即 fail-closed，零写入）**：

1. **writer gate 原样**（`policy.writer=coordinator` ⇒ 只有现任协调者可写；空缺 ⇒ 会话路径拒绝，**设置 UI 仍是兜底**）；
2. **人类确认框**（`userQuestions.ask`）：无确认服务 / 超时 / 取消 ⇒ **拒绝且零写入**（`settings` 逐字节不变、`decisions.md` 零新增）。

**落笔后**：`decisions.md` 追加一行（`形态 → agent-team（Lead=<id>）` 或 `形态 → sessions`）＋ best-effort 重写 `roster.md` 镜像（`DIVERGENCE(8)` D3：`set-mode` 也是一次**设置变更**，镜像自述「与设置变更同一事务内镜像」，所以与既有三个调用点**同形**地调用同一个 `writeRosterMirror`；失败只告警），返回体附**能力矩阵**提示。

**幂等**（`DIVERGENCE(8)` D8 放宽，**这是本轮唯一的门 / 写路径语义改动**—— D2 / D3 只改读面文案与镜像渲染）：`mode` 与 `leadSessionId` 都与现状相同 **且账上已有这一档的形态史行** ⇒ 返回「已是该档」，**不弹框、不写 settings、零写入**；**账上缺那一行**（例如上一次 settings 写成功而 `decisions.md` 写失败、或上一次切换时团队还没有 workspace）⇒ **补记恰好一行**再返回，返回体如实说明这是补记。形态史行的识别走**共享常量函数**（写读同源：落笔与判据读同一个正文生成函数），只比正文、不看时间戳与作者；**账读不出来 / 没有 workspace ⇒ 不补记**并在返回体如实说明（fail-closed，不猜）。**首次声明也算一行**（收尾修复轮 R4 明示的口径）：形态史记的是「**声明过这一档**」，不是「档位发生变化」—— 一个从未切换过的团队第一次收到**它自己那档**的 `set-mode`（例如默认档 `mode=sessions`）同样会**补记一行**，返回体如实标「补记」。**为什么必须补**：`decisions.md` 写失败时给出的指路是「补写路径后重发本次切换以补记」，而幂等分支原先会先命中并零写返回 ⇒ 那条指路**不可执行**，US6「每次切换留一行」会被永久破坏。

### 4.3 读面：`team_link_roster`(get) 与状态卡（A 批）都加「形态」段

读出四件事：

1. **形态**（`sessions` / `agent-team`）；
2. **Lead 会话 id**（agent-team 档）；
3. **成员名册**（**投影**，读时现算）—— 来源标注写死；不可读时**首行按分支取**（`DIVERGENCE(8)` D2 的口径，探针回一个 `cause` 判别符）：
   - 可读：`来源：宿主 agentTeams 投影（本部署可读）`；
   - 不可读且**服务缺席**：`成员名册不可读（本部署未提供该投影）—— 仍可读 Lead 与形态`；
   - 不可读但**服务在场**（缺方法 / 无会话身份 / **调用方非成员** / 读取抛错四条分支）：中性首行 `成员名册不可读 —— 仍可读 Lead 与形态（哪一条读不到，见下一行的原因）`；
   - 两种不可读情形都在下一行给`（不可读原因：…）`，**首行不得与原因行自相矛盾**（改前无条件先打「本部署未提供该投影」，而真机最常走到的恰恰是「服务在场、调用方不是成员」）。
4. **能力矩阵**（**单一事实源 = 父档 §2.3 的表**，本批照抄、不改口径）：

| 能力 | 多会话档 | agent-team 档 |
| --- | --- | --- |
| 跨会话投递（`team_link_send`） | ✅ 主用途 | ❌ 成员是子代理，不是可投递目标 |
| 双门批准 / 配对 | ✅ | ❌ 用不上（宿主那套没有独立信任模型） |
| 换届（`rotate`）/ 恢复（`recover`） | ✅ | ❌ 没有可换届的会话；Lead 会话没了团队就散了 |
| 看门狗（`watch`） | ✅ | ❌ teammate 不是根代理，盯不了 |
| 黑板（decisions / discipline / tasks） | ✅ | ⚠️ 仍可用，但只有 Lead 一方读写 |
| roster 身份 / 版本史 | ✅ | ⚠️ 只记「本团队是 agent-team 档 + Lead 是谁」 |
| 团队状态卡（只读） | ✅ | ⚠️ 成员部分读宿主投影（2026-09-27 已核：本部署已挂载该服务 ⇒ 探针 available=true） |
| 会话深链 / 导出 | ✅ | ✅ 与形态无关 |

**读面必须同时给一句结论**（父档 :67）：agent-team 档应叫「**单会话兜底档**」，不是「另一种平等的形态」—— 多会话不可用时才切，切过去就等于放弃跨会话的全部能力。

5. **形态诊断行**（父档 :50）：若本工作区**除自己外没有其他可达会话**（会话列表快照判据），读面附一行 —— `⚠ 多会话通道看起来不可用（列表里没有其他会话）—— 你可以让协调者切到 agent-team 档（team_link_roster action=set-mode）`。**只提示，绝不自动切**。

> **跨批接缝**：A 批的状态卡（`team_link_status`）本批**加一段形态**；A 批设计 §7 第 6 条已声明「该档下状态卡行为由 B 批定义」。

### 4.4 teammate 交卷提示（步 5，提示式）

**切换的确认框正文里**列出「本次切换不迁移的东西」：

```text
切换后不会迁移：① 信任（配对 / 白名单 / 记忆目标 —— 都要人重新批准）
                ② 成员名册（agent-team 的成员不会变成会话）
                ③ 任务归属（宿主的任务板不跟随；台账仍是本插件的账）
当前 teammate（若可读）：<成员列表> 或（成员名册不可读）
请确认它们的结论已落到黑板或文件 —— 本提示不阻断切换。
```

**判据只做提示式**：不逐成员推断「有没有交卷」（那要读子代理日志，见 §7 不做）。

## 5. 红线

1. **只读宿主**：不 spawn / 不派活 / 不改宿主任务状态；写面只在**自己的** settings 与黑板。
2. **不悄悄降级（**写路径与读路径处置不同，不许混用**）**：
   - **写路径**（切**到** agent-team 的请求）⇒ 宿主能力探测失败即**刺眼报错 + 指路 + 零写入**；
   - **读路径**（名册投影读不到）⇒ 按 §4.3(3) / U11 **如实标注**并保持其余功能可用（形态、Lead、能力矩阵照给）；
   - 两条路都**绝不**把 agent-team 请求当多会话执行。
3. **信任不自动迁移**：切档**一行不写** `pairs` / `trustedSenders` / `rememberTargets`。
4. **双重门 fail-closed**：writer gate 与确认框**缺一即拒绝**，且**零写入**。
5. **指针不拷贝**：agent-team 档只存 `leadSessionId`；成员名册**不落** settings。
6. **切换永远由人触发**：不做自动切档（本插件不自己判断「该切了」）。
