## 一、总体目标

**一句话**：**换届建出来的新会话，自动带着前任会话自己的设置**（至少：预设与模型），而不是每次都退回宿主的全局缺省；**没继承到的必须如实说出口**，绝不假装。

**为什么现在做**（用户 2026-10-13 原话，逐字）：

> 「目前团队换届很麻烦……而且**换了之后新会话还得重新设置权限和模型，不能自动继承老的会话的**」

**为什么这是最容易止血的一件**：插件里**已经有一条路在这么做**（复活路径显式读「这个会话自己存下来的预设」），而**换届那条路把同样的三个变量写死成「无」** ⇒ 修法本质是「让创建面读复活面**已经在读**的东西」，**零新增状态**。

## 二、问题（现象 + 根因，带 file:line 证据）

### 2.1 现象

换届（`team_link_rotate` 的 auto 继任者）与「人改任」的自建继任者，**建出来都是宿主的全局缺省**：模型要重设、预设要重设、（若探针证实可写）审批档也要重设。

### 2.2 根因：**同一个插件里两条路口径相反**（取证见下）

| 路径 | 预设（preset） | 模型（provider/model） | 证据 |
| --- | --- | --- | --- |
| `team_link_rotate` 的 **auto 继任者** | **写死 `undefined`** ⇒ 宿主缺省 | **写死 `undefined`** ⇒ 宿主缺省 | `lib/index.js:8134`（`autoHandover` 调 `createRootAgent(ctx, rootCtx, { preset: undefined, provider: undefined, model: undefined, team })`） |
| 「人改任」的**自建继任者**（reappoint） | 同上，**同一处字面量** | 同上 | `lib/index.js:13981` |
| **复活**（revive） | **读该会话自己存下的** `agent.session.header.agentPreset` | 宿主缺省（既有**有意**偏差，已声明） | `lib/index.js:11058-11102` |

**创建面本身是支持继承的**（缺的只是「传什么」）：`buildTeamSessionCreateOptions`（`:10946`）接收 `plan.preset` / `plan.provider` / `plan.model`，预设经 `resolve → acquireScope → mount` 挂上（`:10975-11014`），`meta` 里落 `agentPreset`（`:11002-11004`），模型对落 `agentOptions`（`:10957`）。

⇒ **一句话根因**：**创建面读的是「计划里有没有人显式给」，而换届这条路从来没给过；复活面读的是「前任自己存了什么」**。两条路对同一件事给出了相反的答案。

## 三、功能用户故事

| # | 用户故事 |
| --- | --- |
| **US-P1** | 作为**维护者**，换届之后我**不用再手设新会话的预设**——它自己带着前任的那个。 |
| **US-P2** | 作为**维护者**，新会话也**沿用前任的模型**（provider/model 一对），不用我重挑。★ **条件（评审 🟡#3 折入）**：**以实施首步的探针 1 为前提** —— 宿主无可读面时，本项**如实报「未继承（原因）」**，不假装（见设计档 §9 边界） |
| **US-P3** | 作为**发起换届的人**，我要在**确认框里就看到「这次会继承什么、没继承什么、为什么」**——设置会跟着会话走，我必须在动手前看见。 |
| **US-P4** | 作为**维护者**，当前任的设置**读不到或已失效**时，**换届仍然能走完**，并且**如实告诉我哪一项没继承、为什么**（不许静默、也不许假装继承了）。 |

## 四、非功能标准

| # | 标准 |
| --- | --- |
| **NF-P1 零新依赖** | 顶层 `import` 仍**恰 8 条**（既有闸门判据：`HOST_IMPORTS` 白名单 + 各批的零依赖锁）。 |
| **NF-P2 零新增政策状态** | **不往 `policy.json` 加任何字段**：继承是**创建那一刻的派生读数**，不是状态。继承结果写进 **prepare 回执** + **交接文档事实段**（既有审计锚）。 |
| **NF-P3 不阻断创建** | 任一继承项读不到 ⇒ **回退宿主缺省 + 具名如实行**；**绝不**因为继承失败而拒绝创建（理由：换届场景前任已冻结，拒绝会把整次换届卡死在无人能修的墙前；见设计档 §4 D2）。 |
| **NF-P4 可核** | 每条继承项都要有**能真红**的判据（把读取源改回 `undefined` ⇒ 判据红），并逐条给红相构造。 |
| **NF-P5 不回归** | `/team_session` 建队路径（调用方显式给 preset/model）与**复活路径**的行为**逐字不变**（既有判据全绿）。 |

## 五、明确的非目标（本批不做）

1. **不迁移会话历史**：继任者仍是空上下文（既有设计的如实代价，本批不改）。
2. **不改「认领」语义**：信任迁移逐项勾选、provisional 回退、24h 自动回退 —— 一个字不动。
3. **不动信任数据**（`pairs` / `trustedSenders` / `rememberTargets`）：那是 claim 段的事，已有机制。
4. **不改 `/team_session` 建队路径**的取值来源（它本来就是「调用方显式给」）。
5. **不做审批档的强制继承**：能不能继承**由实施第一步的宿主探针决定**；探不到就**如实报没继承**（绝不假装）。
6. **不碰黑板 / 台账 / 归档**（那是本系列的第 4 件事）。
7. **不修「撤销依据单槽」**（那是批 0，独立立项；本批只动「创建时传什么」）。
