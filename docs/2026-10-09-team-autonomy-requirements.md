# 需求档 · 团队自治与资源真值（dsh-team-link）

> **状态**：待用户确认（2026-10-09）。本档与同批设计档 `docs/2026-10-09-team-autonomy-design.md` 配对；
> 章节口径＝`METHODOLOGY.md`「设计文档的成文流程与必备章节」（事实源见全局 `~/.dsh/AGENTS.md` 第三节）。
> **两批合并**：consult #26（协调者角色 / 活性推送）+ consult #28（资源真值 / 轮换），合为**一条实施链**。

## 一、总体目标（一段话）

让多会话团队**自己知道自己**：① 团队的**协调者**在任何时刻都清楚「我是协调者、我该干什么、谁在干活」；
② 每个**成员会话**在任何时刻都看得见自己的**真实资源余量**（不是道听途说、也不是模型自己猜的）；
③ 当某个成员确实**太长**（累计/轮次达标）时，团队**看得到该换人**并有一条现成的换人路径。
**一句话**：把「模型自述」降级为「可核对的读数」，把「没人负责的状态」变成「有人看得见的状态」。

## 四、非目标（本批不做；明确登记）

1. **硬墙**（用 `tools.restrict` 摘掉协调者的实施类工具）——技术可行，但会连带堵死"用户让它自己做"，且 PTC 内层解析未实测。
2. **自动轮换**——三家会诊一致：轮换会广播 freeze 并打断在飞的活，本质是人的一次决策。
3. **worker 提示瘦身**（用 scoped section 同名遮蔽掉 openpencil/genui 等无关段，每请求省数千 token）——收益明确但属独立优化。
4. **团队级成本账**（跨会话聚合）——宿主不提供核心能力；本批不做。
5. **改宿主**（CJK 估算校准 / 大包 idle-timeout 识别为疑似溢出 / 真实 usage 回灌压力环）——登记上报。
6. **部署配置修改**（compaction 阈值 / 声明窗口）——属部署面，由用户决定（D-B5）。
