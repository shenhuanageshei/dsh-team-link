## 一、总体目标

**一句话**：把换届的**撤销依据**（信任状态快照）从「**每个团队一个槽**」改成「**每一次换届各存一份**」，让**同时/连续发生的多次换届互不覆盖**。

**为什么这是「整队换届」的前置**（会诊四席**独立**指出的同一条）：

- 现状：`rotationBackup` 是**团队级单槽**（`lib/index.js:1180`），而 prepare **整队覆写**它（`:13207` 的 `{ ...team, rotationBackup: backup, … }`）。
- ⇒ **换第二个角色时，第一个角色的撤销依据被抹掉**。今天「一次只换一个」让这个洞不容易被看见；**一旦批量**（5 个角色连发 prepare），最后只剩**最后一个**的撤销依据 ⇒ **「不可还原」被放大到全队**。
- ⇒ **不修它，任何「整队换届」都是假的**。

## 二、问题（现象 + 根因，带 file:line）

| 面 | 事实 | 证据 |
| --- | --- | --- |
| **写** | prepare 把快照**整队**写进单槽 | `lib/index.js:13207` |
| **形状** | 单槽：`z.any().default(null)`；归一化 `normalizeRotationBackup` | `:1180` · `:1505` |
| **读（4 处）** | 名册镜像 `:6565-6566` · 状态卡 `:7254` · **claim 找前任** `:13277`（`view.teams.find(...)?.rotationBackup?.roster`）· **reappoint 找旧任** `:13540` | 同上 |
| **后果** | 第二次 prepare ⇒ 第一次的 `pairs` / `trustedSenders` / `rememberTargets` 快照**丢失** ⇒ 那次换届**失去对称撤销的还原依据** | 由 `:13207` 的整队覆写直接推出 |

★ **它今天已经发生**：任何「先后换两个角色」的团队，**前一次的快照此刻已经不在盘上**。

## 三、功能用户故事

| # | 用户故事 |
| --- | --- |
| **US-Q1** | 作为**维护者**，当我在同一个团队里**先后/同时换两个角色**时，**每一次换届的撤销依据都还在**，这样任何一次出问题我都能还原。 |
| **US-Q2** | 作为**维护者**，我**现在盘上那份旧格式的快照不能丢**（它是真实历史，不是垃圾）—— 升级之后我仍能在读面看到它、仍能按它还原。 |
| **US-Q3** | 作为**排障的人**，我要在**名册镜像 / 状态卡**上看到**每一次**在飞的换届各自的快照摘要（而不是只有一份）。 |
| **US-Q4** | 作为**claim 的继任者**（或**人改任**的发起者），系统要**按我这次换届**找到对应的那一份撤销依据与前任何 —— **不许张冠李戴**（拿别人的快照来还原我这一路）。 |

## 五、明确的非目标（本批不做）

1. **不做整队换届**（那是下一件：本批只把**它赖以成立的前置**修好）。
2. **不改 claim 的信任迁移语义**（逐项勾选、provisional、24h 回退——一个字不动）。
3. **不改令牌机制**（一次性令牌、30 分钟有效期、认领主体不变）。
4. **不改快照的内容**（仍是 `pairs` / `trustedSenders` / `rememberTargets` ＋ roster；不改字段）。
5. **不动黑板 / 台账 / 归档**（那是第 4 件）。
6. **不重写历史档**：旧格式**只读兼容**，插件**不主动重写**那份旧值（迁移发生在读取时的内存视图与下一次正常写入里）。
