## 一、总体目标

**一句话**：让长期团队能**显式地**把黑板的旧行**搬进归档文件**（只搬不删、可审计），同时**绝不**让任务号/序号回卷、**绝不**自动触发。

**为什么难**（会诊 #66 四席独立命中的同一条）：`decisions` 的 `seq` 与 `tasks` 的任务号**都是从文件里扫出来的**（`lastSeq` / 「扫整个文件」分配 `t-<n>`）⇒ 天真截断会**重置序号**；其中**任务号回卷比 seq 重号更危险**（claim 会指向歧义历史）。另有两个「彩蛋级耦合」（会诊 #66 §2 采纳）：**形态史行**被 set-mode 幂等检查读取、**旧任务号的「已注册」校验**也在同一份文件里 ⇒ 归档切点必须同时尊重它们。

## 二、功能用户故事

| # | 用户故事 |
| --- | --- |
| **US-T1** | 作为**维护者**，当黑板超过**行数阈值（500，具名常量）**时我在读面看到**提示**，但**没有任何东西被自动搬走或删除**；且只要 `archive/` 非空，读面**始终**给一行「另有 M 行已归档至 archive/（最近 <ts>）」（与阈值无关）。 |
| **US-T2** | 作为**维护者**，我要用**显式动词**归档：把 `decisions.md` / `tasks.md` 的旧行**搬进归档文件**；黑板文件里保留尾部与指针；**同一个归档文件只写一次**（同一个文件不重复写/不覆盖），下一次归档开**新文件**。 |
| **US-T3** | 作为**claim 的人**，归档之后任务号**绝不回卷**：`tasks.md` 的下一个 `t-<n>` 必须大于**历史最大值（活跃文件 ∪ 归档）**；**且归档过的旧任务号仍算「已注册」**（对归档 id 的 claim 必须仍被接受，伪造的高于并集最大值的 id 仍被拒）。 |
| **US-T4** | 作为**排障的人**，我要在归档头看到**归档时刻的事实**：时间、执行者、搬走行数与范围、当时各角色的届数快照（**世代只做归档头元数据，不落 policy**）。 |
| **US-T5** | 作为**审计的人**，我要能证明归档**没有丢数据**：归档文件只追加、行数与源文件可对账；**归档磁盘写入与活跃文件重写之间崩溃**时，重跑是**幂等**的（不丢行、不重复、旧归档文件字节不变）。 |

## 三、非功能标准

| # | 标准 |
| --- | --- |
| **NF-T1 不自动** | 行数阈值（500）**只产生提示**；任何搬运都必须由**显式动词**触发（模型/用户在确认框里点）。 |
| **NF-T2 只搬不删** | 搬走的行在归档文件里**逐字保留**；黑板文件侧保留尾部 ＋ **一行归档指针**（不出现「搬走即消失且无指针」）。 |
| **NF-T3 归档文件只写一次** | 同一归档文件**一次成型**（生成后不再追加/覆盖）；下一次归档开**新文件**（文件名带时间戳）。 |
| **NF-T4 序号与注册面不回卷** | `decisions.seq` 与任务号 `t-<n>` 的**分配**与**已注册校验**都必须以「**活跃 ∪ 归档**」的并集为准；严禁只看当前文件。 |
| **NF-T5 零新增顶层键 / 零新依赖** | 归档元数据只在归档文件头里；`policy.json` 键集不变（十一键）；**顶层宿主说明符仍恰 8 条**（要有锁）。 |
| **NF-T6 不改既有读写语义** | `team_link_team_append` / `team_link_team_read`／`set-mode` 的既有行为与判据族不回归；归档是新动词。 |
| **NF-T7 计数与列表同改** | 新增判据会改套件总数 ⇒ README / `CHANGELOG` / 本批两份档同批改准。 |

## 五、明确的非目标（本批不做）

1. **不自动归档**（阈值只提示）。
2. **不删团队、不删黑板文件**（用户已裁定 `bac-1009` 保留）。
3. **不改既有序号分配与注册校验的「时机与格式」** —— 只把**取值面**从「活跃文件」扩到「活跃 ∪ 归档」；不新增顶层状态。
4. **不加 `generation` 顶层字段**（世代只在归档头）。
5. **不动换届 / 信任 / 撤销依据**（那是批 Q/S）。
6. **不做跨团队批量归档**（一次一队）。
