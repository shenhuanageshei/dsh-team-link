## 1. 白话版：这个方案在解决什么

把主会话想成一家店的店长，几个 worker 会话是店员。

- **店员干完活会回来报告 —— 报告必须当面说**（进店长的上下文）。只有当面说，店长才能当场反问、核对、抓出「你记错了」。这套「互相不信、互相核对」是防止一个人记岔了、全体跟着错的关键。
  **所以报告不能改成「写张便条贴墙上，让店长自己看」** —— 那样店长就不会去核对了，便条上的错会被当成事实继承下去。**这一条是整个方案的红线。**
- **但店长的桌子很小。** 十个店员轮流进来讲话，加上老板（你）不断插新指令，桌子很快堆满；更糟的是**店员会定期帮你「清空桌面」**（上下文压缩），而「我们到底在干什么」这份计划，现在只写在店长脑子里 —— 一清空就没了。
- **解法不是让店员少说话，而是把「记账」和「说话」分开**：墙上挂一块**白板**（台账），只记「**谁在什么时候声称了什么**」；真正的结论、证据、反驳，仍然靠**当面说**。店长忘了就去读白板，一读就知道「哦，T-7 是小王在跟，他在等我批」。
- 白板上**永远不写「事实」**，只写「谁声称了什么」。因为白板一旦能写「事实」，店员就会偷懒信白板 —— 核对就死了，而核对是你最不想弄丢的东西。

一句话：**账搬上墙，事留在桌上。**

## 2. 方案本体：五层 + 一条红线

### 2.0 红线：投递层一个字不改

| 现状 | 为什么不动它 |
|---|---|
| 点对点推、**原话**进上下文 | 互核的载体。核对的对象是原话，不是二手摘要 |
| 双门批准（发送方 + 接收方各一次） | 平级会话之间没有天然可信 |
| **未投递即丢**、返回首行 `❌ 未投递` | 「先排队、以后再送」＝把信任决策挪到未来；会诊 2/2 反对持久队列 |
| 插件层**不合并、不摘要、不拦截** | 合并器就是一层摘要，会造出「无署名的二手声音」——没人可怀疑，互核即死 |
| 不做人工分拣台 | 人处理不了这个流量（你的判断，会诊同意） |

### 2.1 第一层：台账（新增一个文件）

- **落点**：`team/<团队名>/tasks.md`，与现有 `decisions.md` **同构**：只追加、每行带署名（作者会话 id）、序号由插件单调分配、单行有长度上限。
- **只写三种行**：派活、接活、**声称**（做完/卡住/需要授权）。以及**第四种：存疑**。
- **它不能改** —— 只能追加。有争议就**再加一行**，不是覆盖旧行。
- **「当前状态」是读的时候算出来的**（每个任务取最后一条主张），并且输出里必须标注「这是派生读数，不是事实」。
- **谁有资格说什么**：派活的人记派活；接活的人只能记自己那条的状态；**任何人**都能对任何一行记「存疑」。反驳和记账走**同一条写入路径** —— 不需要任何新机制。
- **状态永不由投递事件自动推进**：消息送到了 ≠ 事做完了。只有人的显式主张能推进。

### 2.2 第二层：映射（消息 ↔ 台账，用现成的字段）

- 派活时给每件事一个编号：`t-<序号>`。
- 每条回报消息带上 `meta.ref = t-<序号>`（这个字段**今天就有**：≤16 字符、已校验、已渲染在消息 banner 首行）。
- 效果：主会话收到一条回报，不必记得全部计划，看 `ref` 就知道**这是哪件事的更新**；反过来按 `t-` 号也能把相关消息归到一起（**读时算，不建队列**）。
- **零新增存储、零新工具**：这是约定 + 一个读法。

### 2.3 第三层：形态开关（多会话 ↔ agent-team）

- 团队的记录里加一个**形态**字段：`多会话`（默认）/ `agent-team`。**由人指定、可来回切**（你的口径）。
- 插件只报**诊断**（「多会话通道不可用，你可以切」），**绝不自动切**。
- agent-team 档下：
  - **成员名册不由本插件拥有**：只存一个**指针**（Lead 会话 id），成员视图**读时现算**并标注「来源：宿主 Agent Teams」，**一行都不拷贝**进 settings；
  - **只读不写**：不代理宿主的 spawn / 派活 / 改任务状态（既避开实验 API 的 schema 变更风险，也不在两套权限模型之间发明第三套）。
- **能力矩阵（必须如实写进 README 与界面）**：

| 能力 | 多会话档 | agent-team 档 |
|---|---|---|
| 跨会话投递（`team_link_send`） | ✅ 主用途 | ❌ 成员是子代理，不是可投递目标 |
| 双门批准 / 配对 | ✅ | ❌ 用不上（宿主那套没有独立信任模型） |
| 换届（`rotate`）/ 恢复（`recover`） | ✅ | ❌ 没有可换届的会话；Lead 会话没了团队就散了 |
| 看门狗（`watch`） | ✅ | ❌ teammate 不是根代理，盯不了 |
| 黑板（decisions / discipline / tasks） | ✅ | ⚠️ 仍可用，但只有 Lead 一方读写 |
| roster 身份 / 版本史 | ✅ | ⚠️ 只记「本团队是 agent-team 档 + Lead 是谁」 |
| 团队状态卡（只读） | ✅ | ⚠️ 成员部分要读宿主投影（**未复核**） |
| 会话深链 / 导出 | ✅ | ✅ 与形态无关 |

  结论：agent-team 档应叫「**单会话兜底档**」，不是「另一种平等的形态」。**多会话不可用**时才切过去，切过去就等于放弃跨会话的全部能力。
- **切回来**：**信任不自动回迁** —— 旧的配对可能早已过期，必须人重新点一次批准（fail-closed）。
- **切换本身**：记一行模式史进 `decisions.md`，走一次人类确认；**不套换届的令牌机制**（切形态没有「继任者」这个角色）。

### 2.4 第四层：可观测（给人看的一屏）

- 现在这些事实**只有模型读得到**。夜里三点团队卡住，人要知道六件事：谁在跑 · 谁静默多久 · 哪个角色空着 · 有没有在飞的换届令牌 · 看门狗在盯谁 · 台账最后几条。
- 做一张**只读**的团队状态卡（零新信任面）。
- 附带一条**反面预警注记**（会诊提出）：**消息量塌缩、而台账写入增长** ⇒ 大家开始「只写行、不说话」⇒ 互核正在死亡。这是可观测项，不是机制。

### 2.5 第五层：约定（不是机制，写进 `discipline.md` 就生效）

1. **派活即落账**：派活的人当场在台账记一行（带 `t-<序号>`）。
2. **回报必带 `ref`**：回报消息必须挂到对应任务号。
3. **记不清就读台账**，不靠回忆。
4. **验货去查文件与证据，不查白板** —— 白板只是路标。

## 3. 台账长什么样（样例：**拍板前的草案格式**）

> ⚠️ 本节样例是讨论期的**草案**（4 列、任务号写在正文里）。**最终行格式以 §9.3.1 为准**（6 列：`seq | ISO时间 | author | kind | task | 正文`）——实现时不要照抄本节。

`team/<团队名>/tasks.md`（只追加，谁都改不了历史行）：

```text
seq | 时间                | 作者              | 正文
 41 | 2026-09-26 21:10:02 | lead@abc123       | 派活 t-7：让 worker-b 复核 §3 的行号（ref=t-7）
 42 | 2026-09-26 21:12:44 | worker-b@def456   | t-7 接了，预计 10 分钟
 43 | 2026-09-26 21:19:31 | worker-b@def456   | 声称 t-7 完成：核出 3 处错（依据 lib/index.js:3548 / :3550、README §四）
 44 | 2026-09-26 21:21:08 | lead@abc123       | 对 43 存疑：第 2 处我读到的行号不同（依据 …）；已发消息请 worker-b 复核
 45 | 2026-09-26 21:24:55 | worker-b@def456   | 撤回 43 的第 2 处：确认是我读数窗口旧了
```

读的时候：`t-7` 的**最后主张**＝按 seq 取最后一条主张 ⇒ 显示「最后主张 done（… · 已由 #45 撤回 · 撤回者 …）· 存疑已由 #45 消解」。若存疑没被任何后续主张 / 撤回消解，就在**同一行行尾**印 `⚠ 未消解存疑 N 条`（§9.3.3 的形状）—— **绝不按时间戳或序号自动裁决**。**`conflicted` 标签未采用**，被 §9 的措辞纪律取代（§9.3.4 规则 4：一律「最后主张 / 未消解存疑」，读面不得把主张写成事实）。

这个例子里最关键的是 **44 与 45**：**反驳是新增一行，不是覆盖旧行**；而且反驳**只能靠会话之间发消息来消解**，白板只负责记录结果。

## 4. 台账 ≠ 内置任务板（为什么不能照抄）

| 维度 | 内置 Agent Teams 的任务板 | 本方案台账 |
|---|---|---|
| 能不能改已写下的行 | 能（CAS 改状态） | **不能**（只追加） |
| 谁有资格改 | 有权限的成员 | 谁都能**追加**，没人能**覆盖** |
| 冲突怎么表现 | 后写覆盖前写，或过期 revision 被拒 | 未消解存疑**显式**标 `⚠ 未消解存疑 N 条`，摆着不裁决（**`conflicted` 标签未采用**，被 §9 的措辞纪律取代） |
| 一个错误写进去的后果 | 板子自认为现实 ⇒ 全员继承 | 台账只是路标 ⇒ 仍要靠消息核对 |
| 压缩后能否重建全局 | 能 | 能（这是它唯一要干的事） |

内置的任务板能成立，是因为写它的人**都是 Lead 的孩子**、权限继承、天然可信。平级不信任的世界里**没有仲裁者** —— 谁有资格把 `doing` 改成 `done`？没人有。所以只能「谁声称、谁署名、谁反驳」。

## 5. 明确的红线（本方案不碰的东西）

1. 不改投递层：不加持久队列、不合并、不摘要、不拦截、不做人工分拣台。
2. 不抄 CAS 看板，不引入任何「可改状态」的共享结构。
3. 不在 agent-team 档下代理宿主工具、不写宿主状态。
4. 不自动切形态、不悄悄降级（不可用就刺眼报错）。
5. 不新增「会误判的持久状态」：台账是**只追加的可读文件**，不是隐藏状态机。

### 拍板一：台账放在哪？

| 选项 | 做法 | 代价 | 好处 |
|---|---|---|---|
| **A（我建议）** | 新增第三个黑板文件 `tasks.md`，与 `decisions.md` 同构 | 要改 README §四与既有设计档的「黑板两件套」声明（一次文档同步） | 写入路径复用现成的；读面单一；**不碰投递层** |
| B | 塞进 `decisions.md` | 裁决与进行中的活混在一起，读时要过滤；500 字符/行上限更紧张 | 零新增文件 |
| C | 不做台账，只靠约定（worker 自己写文件） | 没有统一读面，压缩后仍无处可查 | 零改动 |

**建议 A**，并且**只做两件事**：只追加 + 读时投影；**不做任何状态机、不做写入校验之外的自动化**。

### 拍板二：形态切换由谁触发？

| 选项 | 做法 | 代价 |
|---|---|---|
| A | 只能在设置 UI 改（人是超级写者） | 半夜要切形态得去开设置 |
| **B（我建议）** | 你跟主管说一声 → 模型调用 → **弹一次人类确认框** → 落笔 + 记一行模式史。没有确认服务时 **fail-closed（不切）** | 需要一次确认交互设计 |
| C | A + B 都要 | 工作量略大 |

**建议 B**（A 作为永远可用的兜底）：你要的就是「说一声就切」；确认框是你们**既有**的模式（换届/恢复都这样），**不引入新的授权类型**。

### 拍板三：teammate 的成果怎么收？

问题：teammate 是子代理，**没有持久身份**。切走形态、解散团队、Lead 会话关闭后，它们做过的事只留在 Lead 会话日志里 —— 那不是本插件的读面。

| 选项 | 做法 | 代价 |
|---|---|---|
| A | 强制交卷（不交卷不让切） | 可能把切换卡死 |
| **B（我建议）** | **提示式**：切换/解散时列出「这些 teammate 的成果还没外化」，由人决定；不阻断 | 不保证成果一定被保留 |
| C | 不做，只在文档里写明这是 agent-team 档的固有代价 | 用户可能不知道要丢东西 |

**建议 B**：你们的红线是「不能悄悄」，不是「必须做」；提示式符合「失败要可见、判断留给人」。

### 9.3 方案

#### 9.3.1 文件与行长格式

```text
<team.workspace>/team/<name>/tasks.md

seq | ISO时间 | author-session-id | kind | task | 正文
```

- `kind` 是**闭集**：`plan`（派活）/ `claim`（接活）/ `done`（**声称**完成）/ `block`（卡住 / 需要授权）/ `dispute`（存疑）/ `retract`（撤回自己此前的某条主张）。
- `task` 形如 `t-<n>`（`^t-\d+$`）；**`kind=plan` 时由插件分配**（与 seq 同类机械动作），其余 kind 必填。
- 正文：单行、非空、≤500 码点（复用 `readBlackboardLine`）。
- seq：**每文件独立计数**（`lastSeq(tasks) + 1`），与 decisions 的计数器互不影响。

#### 9.3.2 写入面（`team_link_team_append`）

新增两个参数：`kind`（file=tasks 时必填）与 `task`（非 plan 必填）。

| 情形 | 行为 |
| --- | --- |
| `kind=plan` | 插件**扫整个文件**取已登记的最大号，分配 `t-<max+1>` 并写行（不可解析行按 U3 的规则忽略、**不重置**计数器）；**调用方若同时给了 task 即拒绝**（消除歧义）。并发两个 `plan` 可能拿到同一个号——与「同 seq」同族的**已知最坏情况**，如实写在 §9.4，**不引入锁** |
| 非 plan 且 `task` 缺失 | 拒绝：「非 plan 必须给 task（形如 t-7）」 |
| `task` 形状非法，或**该号从未在本文件登记过** | 拒绝并提示先 `kind=plan` 登记——这一条正对着「凭记忆转录 id」那类事故 |
| `kind` 不在闭集 | 拒绝并列出闭集 |
| `kind` / `task` 出现在 `file=decisions` 或 `file=discipline` | **拒绝**（一行错误）——防参数误用静默生效 |
| `kind=retract` | 与其它非 plan 相同（必填 `task`）；**不校验**撤回者与被撤回主张的作者是否一致（约定级，见 §9.3.4 规则 2） |
| 正文含换行 / 空 / 超 500 码点 | 拒绝（沿用既有文案风格） |
| 团队不存在 / 无 workspace | 沿用既有文案 |

成功返回值给出 `seq`、`task`（plan 时是新分配的）、`author` 与文件路径——与 decisions 分支的返回形状同族。

#### 9.3.3 读面（`team_link_team_read`）

在 discipline 块之后追加：

```text
--- tasks.md（只追加台账；显示末 20 条）---
共 N 行，显示 20 条 · baseHash=<16hex>（仅供参考/审计：tasks 只追加、不接受 baseHash）
（派生读数：扫描最近 500 行；逐任务给「最后主张」与「未消解存疑」——是读数，不是裁决）
- t-7 · 4 行 · 最后主张 done（2026-09-26 21:19 · worker-b@def456）· ⚠ 未消解存疑 1 条
- t-8 · 2 行 · 最后主张 claim（2026-09-26 21:10 · lead@abc123）
（原始行）
42 | 2026-09-26T...Z | lead@abc123 | plan | t-7 | 让 worker-b 复核 §3 的行号
```

边界（逐条如实标注）：文件不存在 →「（文件不存在，按空处理：0 行）」；超过扫描上限 →「（派生只扫描最近 500 行；更早的 N 行未参与派生）」；不可解析行 →「（N 行无法解析，未参与派生）」。

#### 9.3.4 派生规则（严格定义，不许自由发挥）

对某个 `task`，取其全部行按 seq 升序：

1. **最后主张** ＝ 该任务中 `kind ∈ {claim, done, block}` 的**最后一条**；一条都没有 →「尚无主张（仅登记）」。**若其后存在 `retract` 行**，该主张**不删除**（只追加台账不抹历史），呈现为「最后主张 done（**已由 #N 撤回** · 撤回者 …）」，并同时保留原主张的作者；**多条撤回时 `#N` 取最后一条撤回行**（与「最后一条主张」同一条取法），撤回**条数不另印**（原始行里本就看得到，§9.3.4 不做自由发挥）。
2. **未消解存疑** ＝ 存在 `kind=dispute` 的行，且在其之后**不存在**该任务的 `claim / done / block / retract` 行 → 标 `⚠`；否则标「存疑已由 #<seq> 消解」。**两条子情形在此定死**（实现即此，各由一条断言钉住）：① **同一任务同时存在未消解与已消解存疑时印 `⚠`**（`if` 分支优先，「存疑已由 #N 消解」那一支不再出现）；② **多条存疑都已消解时，`#N` 取「最后一条被消解存疑的**首个**应答行」的 seq**（不是它之后的那一条应答行，也不是更早那条存疑的应答行）。**作者关系不在派生里强制**（黑板无写权限门，见 §9.4）：任何会话都可追加 `retract`，读面如实显示「主张者」与「撤回者」两个 id，由人判断这够不够。
3. **绝不自动裁决**：派生只做「取最后一条 + 看其后有没有新主张」，不比较正文、不按时间戳裁冲突。
4. **措辞**：一律「最后主张 / 未消解存疑」；不得输出「状态＝完成」这类把主张写成事实的词。

### 9.4 边界与红线

- **只追加**：`appendFile`，不重写；并发追加最坏同 seq、**不丢行**（沿用 decisions 的既有论证）。
- **并发分配 `t-<n>` 的已知最坏情况**：两个 `plan` 同时扫到同一个最大号时会撞号。黑板**无锁**（既有纪律），因此这与「同 seq」同族、**如实声明而不消除**；撞号时该号下会多出一行 `plan`，读面照显。
- **闭集**：`file` 白名单三值，绝不接受路径形状；`kind` 闭集；`task` 形状校验；**`kind` / `task` 与 `file≠tasks` 的组合一律拒绝**（防参数误用静默生效）。
- **无写权限门**（与黑板一致）；作者身份照记，无会话身份记 `unknown`。
- **派生是读数**：删掉 `tasks.md` 不影响任何写入路径；派生结果随时可从原始行重算。
- **零新持久状态**：不新增 settings 键、不引入内存态。
