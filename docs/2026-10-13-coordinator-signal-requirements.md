## 一、总体目标

**一句话**：让「**协调者自己闷头干、三个队员在旁边闲着**」这件事**变得刺眼**，
并让它**没有理由去读队员的会话历史**（那会把自己的上下文吃掉）。

**为什么值得做**：2026-10-13 凌晨真机 —— `bac-1009` 队的协调者**自己承认**两处越界：
① 自己算了构建产物的哈希（本该派给 worker-2）；② 两个 worker 空闲，它却在做记账与文档；
③ 拿一句**未经复核的自陈**当理由，把一名队员排除在派工之外**并复述了几个小时**。
黑板同期逐字记着：「维护者当场质询『worker 在干活吗？你怎么自己干？』⇒ 我逐条自查并立刻纠正用工失衡」。

**关键事实（决定了这批的性质）**：**规则早就写进它的系统提示了** ——
`lib/index.js:3793` 的 `renderCharterLines` 逐字包含
「**你只做：管理/协调/决策/评审/设计；不实施**」「实施一律派给团队成员」「开工先看状态（谁在跑/谁空闲/谁需处置）」
「**成员「空闲」= 待派工，不是故障**」。⇒ **这批不是「补规则」，是「让规则更难被忽略」。**

## 二、问题（现象 + 根因，带 file:line 证据）

### 2.1 现象（真机读数，2026-10-13 凌晨）

| 项 | 读数 | 来源 |
| --- | --- | --- |
| 协调者 | 运行中（`team-link-bac-1009-coordinator-fb1951d4`，后换届为 `e3d1aa13`） | 团队状态卡 |
| 三个队员 | **全部空闲** | 同上 |
| 当时真正在跑的东西 | 一个**宿主子代理**（不是队员） | 会话面 |
| 协调者的越界 | 自认 3 次（R136 / R139 逐字） | 黑板 `decisions.md` |
| 「队员窗口 99%」 | **无任何读数支持**（唯一依据是队员几小时前的一句自陈） | R139 自述 |
| 状态卡自带的判读 | 逐字：「本系统按压力自动压缩，**结构上不存在『预算耗尽』**」 | 状态卡第 ⑧ 段 |

### 2.2 根因（三条，带 `file:line`）

**根因 1 · 「有活没派」的信号太软，且被「不打扰」门关掉。**
工作台摘要今天把「空闲待派」渲染成**一行散文**（`lib/index.js:3148`），
并且**只有「有可行动内容」时才投**（`watchdogDigestActionable`，`:3116`），
还有 **10 分钟去抖 + 指纹去重**（`:3343-3346`）。
⇒ 「三个队员全闲着」这类**最该刺眼**的形态，与「刚转空闲」等噪音**同一档处理**。

**根因 2 · 没有任何信号在协调者「快把自己的窗口读满」时拦它。**
资源行今天把「压力」渲染成冷冰冰的一个百分比（`:3781`），
**没有任何阈值告警**，也没有任何地方写着「别去读别人的历史」。
⇒ 协调者为了「看队员在不在干活」去读队员的会话，把对方窗口装进自己的窗口。

**根因 3 · 「事实源」指路不明。**
宪章第 3 条只说「开工先看状态」（`:3798`），**没写「要看队员在干什么，读黑板 tasks，不要读它的会话历史」**。
⇒ 协调者只有一条它自己摸出来的路：读对方的上下文预算。

## 三、功能用户故事

| # | 用户故事 |
| --- | --- |
| **US-J1** | 作为**维护者**，当**队员空闲而协调者自己在干活**时，我要这条事实**主动、显眼**地出现在协调者面前（而不是埋在摘要第 3 行、还可能被去抖吃掉）。 |
| **US-J2** | 作为**协调者**，当**我自己的上下文压力偏高**时，我要收到一条**点名后果**的告警（「再读别人的历史会把自己读爆」），而不是一个需要我自己解读的百分比。 |
| **US-J3** | 作为**协调者**，我要知道**「要看队员在干什么，该读哪里」**（黑板 `tasks.md`），这样我**不需要**去读它的会话历史。 |
| **US-J4** | 作为**维护者**，我要这些信号**不刷屏**（有去抖、有上限、只在真有事时说），否则我会把它整个关掉。 |

## 四、非功能标准

| # | 标准 |
| --- | --- |
| **NF-J1 零新依赖** | 顶层 `import` 仍**恰 8 条**（本批只用既有符号）。 |
| **NF-J2 不打扰上界** | 新增的告警档**必须有去抖**；「无事不打扰」这条既有口径**不得被放宽成「每轮都投」**。★ **评审 🔴#1 的裁决（父侧 2026-10-13，取代原写的「同一状态不重复」）**：「有活没派」这一档**允许窗口外复投**（每 ≥10 分钟一次），但**每段连续状态至多 3 次**（「段」＝ 同一组空闲成员的签名；签名一变即重置计数）。理由：本批的目标是「**让信号不沉没**」（bac-1009 那次持续了数小时，一次性告警错过就永久没了），而**限量**保住了「不刷屏」。压力告警则沿用**同一档不重复**（档 = 每 10% 一档）——两者口径不同，**各自写明**。 |
| **NF-J3 反走私不变式** | 所有新增文本**只能由插件常量组成**，插值的只有状态字段（会话 id / 判定词 / 时间戳），且**必须过既有消毒出口**（`noticeField` / `wellFormed`）—— 与 `renderWatchdogDigest`（`:3140`）同一约束。 |
| **NF-J4 可核** | 每条新增信号都要有**能真红**的判据（去掉那一步 ⇒ 判据红），并**逐条给出红相构造**。 |
| **NF-J5 不误伤既有行为** | 摘要的**行数预算**与既有四组语义**不变**；`TICKABLE_VERDICTS`（失联三态）**不许扩**。 |

## 五、明确的非目标（本批不做）

1. **不试图拦截「协调者自己干」**：那一步走的是**宿主子代理工具**（不经过本插件任何工具）
   ⇒ **插件拦不住**。本批只把事实**变得更刺眼**，**不假装能阻止**。
2. **不替协调者做派工**：不自动派活、不自动改台账。
3. **不动失联三态**（`silent-idle` / `goal-disarmed` / `dead`）：那是另一件事，语义不同。
4. **不改阈值语义**：不引入「低于某阈值才算正常」这类比较口径（沿用既有纪律：只给读数 + 结论）。
5. **不做「零代码诊断页」**（那是可选交付物，本批只做插件信号；要做**另行立档**）。
