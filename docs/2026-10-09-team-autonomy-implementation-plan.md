## §4 D-B5 部署配置补丁（**不在本仓**，需你确认后我再落地）

**现状**（profile 里 `compaction-basic` **零配置** ⇒ 默认 `thresholdRatio 0.8 / headroomTokens 65536`）：

| qax 路由 | 声明窗口 | maxTokens | 现行阈值（估算口径） | 按 1.89× 换算的真实触发点 |

| `glm-5.3-internal` | 400,000 | 131,072 | `min(320000, 203392) = 203,392` | ≈ 384 K |

**建议补丁**（`C:\Users\huangchaowen\.dsh\profiles\desktop\cordis.patch.yml` 追加；`id` 对齐 `dsh-base` 的 loader 条目 `compaction-basic`）：

```yaml
# 2026-10-09 · 团队自治批 D-B5：按「真实 token」校准压缩阈值
# 默认 0.8 假设 window 数字可信；实测本地估算器对中文低估 ≈1.89× ⇒ 真实触发点远超声明窗口
- id: compaction-basic
  config:
    auto: true
    thresholdRatio: 0.28
    headroomTokens: 131072
```

**效果**：deepseek 两条 → 阈值 `min(280000, 475712) = 280,000`（估算）≈ **529 K 真实**；glm-flash → ≈ 486 K；glm-internal → ≈ 212 K。全部落在声明窗口内。
**代价（如实）**：压缩更早 ⇒ 摘要调用更频繁（每次摘要本身是一笔大 API 调用）；这是"少撞墙"与"少花钱"的取舍。**前提**：网关真实窗口**未验证**；若你确认网关确实支持 1M，可把 `thresholdRatio` 放宽到 0.35–0.4。
**生效方式**：改 profile 配置**需重启 DSH**（重启会打断在飞作业 ⇒ 按本仓纪律"重启前先确认无在跑作业"）。

**⚠ 待定（2026-10-09 用户追问后重开）**：用户问「为什么降到 280k？明明模型是 1M 上下文」——该追问成立，取值**尚未定**。三条口径对照：

| 方案 | thresholdRatio | 引擎口径（估算） | 按 1.89× 换算的真实触发点 | 占声明窗口 |
| --- | --- | --- | --- | --- |
| **现状（零配置默认 0.8）** | 0.8 | 541,248 | **≈ 1.02 M** | **102%（已越界）** |
| 原稿（激进） | 0.28 | 280,000 | ≈ 530 K | 53% |
| 折中（目标：真实占八成） | **0.42** | 420,000 | ≈ 794 K | 79% |
| 不改（等宿主修） | — | 541,248 | ≈ 1.02 M | 102% |

**澄清（重要）**：280K **不是"只给模型 28% 的上下文"**——那是**本地估算单位**；估算器对中文重上下文实测低估 **≈1.89×**，故 280K 估算 ≈ **530K 真实**（约真实窗口一半）。
**父侧建议**：① 先花 30–60 分钟统计 4 个 worker **每次压缩事件**的「估算 vs API 实测」（样本 1 条太薄）再定比值；② 若不想等，取**折中 0.42**（≈ 真实八成），而非原稿的 0.28。
**本条属部署面，且不在插件实施链的临界路径上** —— 定与不定都不阻塞批 1/2/3。

## §5 并行度与工期

### 5.1 硬约束（为什么"并行开发"有限）

1. **一个会话同时只能跑一个 `eng_coder`**（平台约束）⇒ 代码批**天然串行**。
2. **三批都改同一个 `lib/index.js`（12 053 行）与 `host-half.test.mjs`** ⇒ 本仓纪律要求"同一棵树不并发两个写者"。
3. 因此**真正并行**的只有：批 0（用户操作）、批 0.5（部署配置，不同面）、以及**每批的独立复核**与**下一批的准备/文档**。

### 5.2 两种编排

| 编排 | 做法 | 净工时 | 墙钟（含等待） |
| --- | --- | --- | --- |
| **保守（推荐）** | 单树串行：批 1 → 批 2 → 批 3；配置与复核插空并行 | 4.5–6.5 h | **约 1 个工作日**（含 G1 与确认间隙） |
| 激进 | 两个 worktree：批 1 ∥ 批 2，批 3 收口 ⇒ 多一次合并 + 双份 check 读数 | 3.5–5 h | **3.5–5 h**（含合并风险） |

## §6 风险与回滚

| 风险 | 概率 | 缓解 |
| --- | --- | --- |
| 设计评审出 🔴（如"提示段属新依赖"被判阻断） | 中 | 设计已含降级面与三条待实测；若被判阻断，按裁定改档重审 |
| 批 1 引入回归（watchdog 是既有被测面） | 中 | U9–U12 + 既有三态断言全绿；红相必须先跑出来 |
| 重启打断在飞作业（批 0.5 与真机冒烟都要重启） | 高 | 重启前确认无在跑作业；先 `git stash create` + `refs/wip/<名>` 上保险 |
| **令牌与文档集指纹绑定**：评审通过后、派单前**再改被审文档** ⇒ token 失配（D-30「文档已变更」态）⇒ eng_coder 起不来 | 中（**2026-10-09 已实踩一次**） | 纪律：**评审 PASS 到派单之间，被审文档一个字都不改**；若必须改 ⇒ 先重审拿新 token（重审由用户点火）；排障信号：eng job 秒级失败 + 子会话只有 header + 报告为空 |
| **同树并发跑 check 会假红**（共享固定临时目录 ⇒ ENOENT / ENOTEMPTY / 计数漂移） | 高（**2026-10-09 已实踩**：父侧 A=0/B=13；验证者 ENOTEMPTY at :1954） | 纪律：**跑 check 前先确认同树无并发跑者**；批 1 已把临时根改为每进程唯一（`mkdtempSync(os.tmpdir())`），修后 2 路/3 路并发均 1375→1376/0 绿 |
| **核「零残留」类断言时 PowerShell 忽略大小写**（`Select-String` 默认大小写不敏感 ⇒ 既有英文散文假阳性） | 中 | 纪律：这类断言一律加 `-CaseSensitive`；2026-10-09 复核实测：不加报 2 条假阳性，加后 0 |
| **报告措辞与代码不一致**（本次诱因：把 `onAttach` 的即时开火描述成 attach 内触发 ⇒ 有人顺手补了一处**未申报**的调用） | 中（已实踩并按裁定撤回） | 纪律：**默认改措辞**；功能确需补调用 ⇒ **先申报再动手**（未申报的扩张一律撤回，事后不追认） |
| 宿主换代导致提示段面消失 | 低 | 特征探测 + 降级到"工具返回重钉"（U1） |

**回滚**：每批一个提交（pathspec，禁裸 `git commit`）；`link:` 接线 ⇒ 回滚＝`git revert` + 重启。
