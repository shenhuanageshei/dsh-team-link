## 1. 背景

DSH STORE 的**上架自动检查**（每 8 小时扫固定 commit）在 [issue #1380](https://github.com/AI-Scarlett/DSH-Store/issues/1380) 判定本插件 `catalog-blocked`，并列出**确定性原因**与三条修改建议。商城原文明确：**这不是安全漏洞指控，也不表示项目质量有问题**，只说明当前固定源码**尚未满足可安装/自动更新契约**。

用户裁定：**先做便宜的（`engines` + 依赖说明）**，再由本批承接**唯一的硬阻塞（单文件拆分）**与**装/启/卸证据**。

---

## 2. 问题（根因，带证据）

**逐字取证见需求档 §二**（本档不复写整表）。三条要点：`lib/index.js` = **1,092,693 B**（上限 262,144，**越限 4.17 倍**）· `package.json` **无 `engines`** · 运行时依赖恰 1 个（`schemastery`）但**声明面缺失**。

**为什么单文件会这么大**：宿主半边（名册/换届/黑板/投递/看门狗/工具注册/段渲染/崩溃现场…）长期在**一个文件**里演进，共约 **16.3k 行** ⇒ 越过商城按文件计的自动审查上限。**这不是质量问题，是打包形态问题。**

---

## 3. 目标 / 非目标

**目标**：① 每个运行文件 **< 262,144 B** ② 显式声明 Node 范围 ③ 依赖/权限/外部服务/失败边界**可读**（合规档已立）④ 装/启/卸**有证据** ⑤ **对外行为零变更**。
**非目标**：需求档 §五 七条（不改行为 · 不动 `client.js` · 不上构建工具 · 不加依赖 · 不追商城没提的项 · 不改宿主兼容区间 · 文档留在 `files`）。

## 4. 决策与理由

| # | 决策 | 理由 | 被否决的备选 |
| --- | --- | --- | --- |
| **D1** | **按领域拆**（候选六域：`policy-store` 名册与状态落点 / `rotation` 换届与恢复 / `ledger` 黑板与台账 / `messaging` 投递与列表导出与屏蔽 / `watchdog` 看门狗·工作台·心跳 / `registration` 工具注册与段渲染），**不按行数均分** | 领域边界是**可读性**与**后续维护**的唯一有效分界；按行数均分会把相干函数劈开，制造隐性耦合 | ① 按行数均分（**可读性最差**）② 只做「一大一小两档」凑数（下批再超限，返工） |
| **D2** | **`lib/index.js` 保持为入口与主装配**（`exports` 四项、`main` 一字不改），其余域抽成 `lib/*.js` 由它导入/再导出 | 入口面是**对外契约**（`package.json` 的 `exports`）⇒ 不动它就把外溢面压到最小 | 改 `exports` 指向新入口（**动对外契约**，且商城要重审入口） |
| **D3** | **模块间只走相对导入**（`./xxx.js`）；本仓「顶层 `^import` **恰 8 条**」闸门**同批改写**为**只数宿主说明符**（白名单内 8 个），内部相对导入不计入 | 拆分必然引入内部导入 ⇒ 旧口径**必然被打破**；闸门要守的是「**不引入新的宿主依赖面**」，不是「文件里只能有 8 行 import」 | 保留旧口径（会假红；若为过闸而合并文件则与 D1 冲突） |
| **D4** | **纯机械搬运**：只做「移动函数 + 补 `export`/`import`」，**不改一行逻辑**；每一步之后**立即跑两套件**，红则回滚该步 | 1697 + 310 条断言就是这次重构的**安全网**；「顺手改一点」是这类重构翻车的唯一原因 | 借机整理/重命名/优化（**本批零容忍**：任何行为变更都不属于「上架合规」） |
| **D5** | **切 ≥5 档、目标每档 ≤220 KB**（按 1,092,693 / 262,144 = 4.17 计算，5 档才有缓冲；220 KB 留 16% 余量给后续增长） | 贴着上限切（如正好 256 KB）会在下一次加功能时**立刻回红** | 切 4 档贴着上限（**必然返工**） |
| **D6** | **`engines.node` = `>=22`**，并在 README「宿主版本支持」表同步一句；**降限条件写死**（在 Node 20/22 实跑两套件全绿才降） | 我们**只真跑过**宿主的 Node **v24.14.1**；写 `>=18` 是**没验过的承诺** | 写 `>=18`/`>=20`（**不诚实**）· 不写（商城继续 blocked） |
| **D7** | **装/启/卸证据 = 手工实测 + 记账**（新建空 profile → `link:` 装入 → 启动确认工具面在场 → 卸载 → 启动确认消失且无残留），输出原文进 `docs/verification-log.md`；**不自动化、不阻塞本批交付** | 一次性动作，自动化成本远高于收益；且它**不是** `catalog-blocked` 的硬阻塞项（商城要求的是「evidence」，不是脚本） | 写成可复现脚本（**过度工程**，且要引入宿主不保证的接口） |

## 6. 机制伪代码（拆分契约：前置 / 后置）

```
拆分不变量（每一步都必须同时成立）：
  ① 入口面不变：`package.json`.main / exports 四项 / dsh.bundle / dsh.client 逐字不动
  ② 宿主依赖面不变：宿主说明符仍恰 8 个（`HOST_IMPORTS` 白名单逐字）
  ③ 模块图无环：`lib/*.js` 的导入图 acyclic（禁 A→B→A）
  ④ 无副作用搬家：被搬的函数**只带它自己的依赖**（必要的常量/助手一并搬或从共享档导入）
  ⑤ 每档 ≤ 262144 B（目标 ≤220 KB）

一个域的搬运（前置 → 后置）：
  前置：函数 f 在 lib/index.js 内定义并被 n 处引用
  动作：把 f 连同它**只被自己用**的私有助手/常量搬到 lib/<域>.js 并 `export`;
        在 lib/index.js 里改为 `import { f } from "./<域>.js";`
  后置：`node --check` 三个文件全过 ∧ 两套件全绿（1697 + 310）∧ 该档字节 < 262144
         ∧ 模块图仍无环 ∧ 宿主说明符仍 8 个
  失败：**回滚这一步**（git checkout 该文件），不要「继续拆再回头修」
```

**边界规则**：**共享物**（`PLUGIN_LABEL`、`wellFormed`、`noticeField`、`POLICY_KEYS` 等被多域使用的符号）**抽到一个 `lib/shared.js`**，各域从它导入 ⇒ **共享档也不许超过上限**（实施首步先量它）。
**禁止**：为了「少一次导入」把函数复制两份（**双事实源必漂移**）。

**入口 `lib/index.js` = 254,802 B**（对外契约逐字未动：`main` / `exports` 四项 / `dsh.bundle.patch` / `dsh.client`，判据 `Rr2`）。

## 9. 边界

| 情形 | 行为 |
| --- | --- |
| **拆分中出现循环依赖** | **当场停手**：改由「把共享物下沉到 `shared.js`」或「把该函数整体搬到更合适的域」解决；**禁止**用「延迟导入/运行时 require」绕过 |
| **某档仍超限** | 继续按领域细分（`messaging` 可再分投递/列表导出）直到满足；**不许**把超限归因成「商城太严」而不修 |
| **搬运中行为漂移（套件红）** | **回滚该步**（`git checkout` 该文件）→ 定位 → 再前进；**不许**改判据来「适配」新行为 |
| **入口面被迫改动** | 视为**设计变更**：停下、更新本档、重新走评审（D2 是红线） |
| **商城复检仍 `blocked`** | 按**新开单的原因**另行立项（本档不猜原因）；本批的本地门槛**已经达成**，不因此回滚 |
| **`engines` 声明导致老环境装不上** | 这是**有意的**（诚实声明 > 宽区间）；降限走 D6 的写死条件（Node 20/22 实测全绿） |
| **失败方向** | **fail-closed 于对外契约**（入口面/行为一旦存疑就停下）；**fail-open 于内部布局**（模块划分是内部事，可迭代） |
| **重启** | 拆分是**纯源码布局**变更 ⇒ **部署仍走 `link:`**，生效需重启（**由用户决定时机**，代理不自作主张） |
