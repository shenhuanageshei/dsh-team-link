dsh-team-link

跨会话团队协作层 —— 让多个 DSH 会话成为一支有身份、有信任、有账、有形态的队伍。

版本 v0.4.0 10 个模型可见工具 断言 1203 + 269 与宿主 Agent Teams 正交

它解决什么三个痛点

会话之间没有身份

谁是主管、谁是 worker、谁换了人、谁下岗了 —— 没有任何地方记着。

会话之间没有信任

能不能发消息？谁批准？发出去之后对方到底动了没有？

会话会失忆

主会话被压缩后，计划与结论散落在历史里，醒来只剩一句「继续」。

三层结构身份 / 黑板 / 可观测

① 身份与信任层

roster 名册（创建即认领 · 换任 · 退役 · 版本史）· 双门批准与配对（双向免确认）· rotate 换届与 recover 恢复。

② 黑板层

decisions 只追加裁决 · discipline 乐观锁纪律 · tasks 只追加任务台账（读时投影：最后主张 / 未消解存疑，措辞禁用事实化）。

③ 可观测与形态层

list_sessions 有界读窗（点名读 + 分页）· team_link_status 一屏状态卡 · 形态：多会话档 ↔ agent-team 档。

两档拓扑多会话档 ↔ agent-team 档（人确认后才切）

两档可切：形态由人在对话里指定 → 弹一次确认框 → 落笔并记一行形态史。绝不悄悄降级；切回多会话档时信任要人重新批准。

与宿主 Agent Teams 的关系正交，不是竞争

维度dsh-team-link宿主 Agent Teams
边界跨会话 / 跨进程单会话内的父子（Lead + teammate）
身份团队名册 + 版本史（谁换过任）子代理生命周期
信任独立模型：双门批准 · 配对 · 换届吊销无独立信任模型
结论两者可共存：多会话时用前者，通道不可用时切到后者（形态开关，人确认后才切，绝不悄悄降级）。

纪律本仓的验收文化

  • 红相必红：每个修复都要给出「修复前必红 / 修复后全绿」两次实测读数。
  • 声称必须可核：每条「有断言」的声称附可 grep 到的断言名；每条读数附命令与原文。
  • 「0 命中」要用真能区分的检查得出（假阴性比没检查更贵）。
  • 三道门：分歧审计 → 修复轮 → 代码评审；缺一不合并。
