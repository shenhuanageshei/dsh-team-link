# 批 S · 整队换届（批量准备 ＋ 各自认领）—— 需求档

> 本档只写**要解决什么**（三层：总体目标 / 功能用户故事 / 非功能标准）与**明确的非目标**；怎么做放设计档 `docs/2026-10-18-team-rotation-design.md`。
> **输入**：会诊 #66 裁定层 §3（`docs/consult-minutes/2026-10-14-consult-66-minutes.md`）· 交接档 `docs/2026-10-18-handover.md` 的 A-3 口径 · 用户 2026-10-18 授权（自主立项、重大设计经会诊）。
> **前置**：批 Q（撤销依据按换届各存一份）必须先落地 —— 单槽取消依据下的任何「批量」都是假的。批 Q 的判据 `Qr1`–`Qr11` 已在宿主套件里。

---

## 一、总体目标

**一句话**：让**现任协调者**用**一条命令 + 一道人类确认框**把**整队 N 个角色**的换届**准备阶段（Phase A）**一次做完 —— 每个角色各有一条 pending、各有一份撤销依据、各有一枚绑定三元组的令牌；**认领阶段（Phase B）一个都不省**，仍由每个继任者本人凭令牌完成。

**为什么这是痛点**（逐字来自会诊 #66 四席独立指认）：

- 今天 `team_link_rotate action=prepare` 只能由**该角色现任**发起、`role` 必填 ⇒ 5 人队要 5 个不同调用方会话各跑一次，协调者无权代 worker 发起；
- 单槽 `rotationBackup` 已被批 Q 换成 `rotationBackups`（按 rid 各存一份）⇒ 批量准备的**存储前置**已经成立；
- 令牌自治是机制红线：**任何「一把换完」都不成立**，批量的边界只能切在 Phase A。

## 二、功能用户故事

| # | 用户故事 |
| --- | --- |
| **US-S1** | 作为**现任协调者**，我要用**一条命令**发起整队换届准备：插件先做**预检**（auto 角色的交接文档硬节齐全、继任者候选算得出来），再弹**一道**人类确认框，确认后**一次**策略写盘落下全部 pending 与撤销依据。 |
| **US-S2** | 作为**继任者**，我仍然**自己**凭令牌 `claim` —— 批量**不代认领、不代批准**，provisional / 24h 回退语义一个字不动。 |
| **US-S3** | 作为**发起人**，我要**按角色**看到结果（N 个角色各自：准备成功/失败原因、令牌掩码、认领状态），部分认领时如实报 `k/N`，不假装整批成功。 |
| **US-S4** | 作为**排障的人**，我要在批量进行中看到**这一批**的每个角色各自的状态，并且**批次存在期间**有人再发单角色换届时得到**具名拒绝 + 指路**，而不是互相踩。 |
| **US-S5** | 作为**协调者**，我自己的角色**排在最后**准备 —— 否则驱动批次的人先把自己换掉，后半批次成了孤儿驱动。 |

## 三、非功能标准

| # | 标准 |
| --- | --- |
| **NF-S1 单写点 ＋ 失败契约分层** | Phase A 的**全部** pending ＋ 撤销依据在**一次** `policy.update` 里落盘（沿用既有唯一写点）。★ **会诊 #101 折入**：**预检失败 / 确认前中止 ⇒ 零副作用**（`agents.create` 零调用、`policy.update` 零次、广播零次）；**确认后执行期失败 ⇒ 不再承诺零副作用** —— 已产生的副作用（已建会话 id）必须**逐项如实报告**并可幂等重试，**不做假补偿**（平台无删会话原语）。 |
| **NF-S2 令牌时限 2 小时** | 批量铸出的令牌 **TTL = 2 小时**（单角色仍 30 分钟）。理由：N 个继任者要各自找时间认领，30 分钟会把批量变成「必然部分过期」；**代价如实**：令牌可用窗口变长，故仍保持一次性、绑三元组、成功即作废。 |
| **NF-S3 发起权与信任** | 发起 = **该队现任协调者** ＋ 既有 writer gate ＋ **一道**人类确认框（无确认服务/取消/超时 ⇒ fail-closed、零写入）。**不做**「任一成员可发起」。 |
| **NF-S4 零新增顶层键 / 零新依赖** | `policy.json` 顶层键集**不变**（十一键）；宿主说明符仍 8 条；批次状态**只在团队行 / roles[].pending 内部**，不落新顶层字段。 |
| **NF-S5 不改 claim** | claim 的信任迁移、逐项勾选、provisional、回退、令牌三段绑定**一个字不动**；既有 M4 判据族全绿。 |
| **NF-S6 限速按角色** | 限速键仍是 `(team, role, 10min)`；整批计作**每角色一次**。批次内重发 ⇒ 逐角色拒绝并列出剩余窗口。 |
| **NF-S7 计数与列表同改** | 新增判据会改套件总数 ⇒ README（徽标 / 稳定性行 / 当前读数行）· `CHANGELOG` · 本批两份档**同批改准**。 |

## 四、可验判据（`host-half.test.mjs` 新增「批 S」块，标识符 `Sr` 中缀；初稿，设计档定稿）

| # | 判据（摘要） | 红相（怎么让它红） |
| --- | --- | --- |
| **Sr1** | 一次 `prepare-batch` ⇒ 恰 **1 次** `policy.update` 落盘；每个角色各一条 pending（带 `rotationId`），团队 `rotationBackups` **恰 N 条**且各自快照可辨 | 逐角色各写一次 / 只写最后一个 ⇒ 红 |
| **Sr2** | 每枚令牌绑定 `(team, role, successor)` 三元组、**TTL = 2h**、一次性 | TTL 仍 30min 或未绑定 ⇒ 红 |
| **Sr3** | 无确认服务 / 取消 / 超时 ⇒ `agents.create` 零调用、`policy.update` 零次、广播零次 | 先建会话再问 / 取消后仍有写 ⇒ 红 |
| **Sr4** | 预检：任一 auto 角色交接文档缺硬节 ⇒ 整批拒绝、零副作用、逐角色点名缺什么 | 缺节照建 ⇒ 红 |
| **Sr5** | 发起权：非现任协调者 ⇒ 拒绝；writer gate = `coordinator` 时非现任一律拒 | 放宽为任一成员 ⇒ 红 |
| **Sr6** | 排序：协调者自己的角色**最后**准备（回执顺序可核对） | 协调者排第一 ⇒ 红 |
| **Sr7** | 部分认领：role1 claim 成功、role2 令牌过期 ⇒ 清扫**只**取消 role2，roster 呈 mixed 态，回执报 `1/2` | 整批一起取消 / 假装全成功 ⇒ 红 |
| **Sr8** | 批次在飞期间再发单角色 prepare ⇒ **具名拒绝 + 指路**（不踩批次） | 允许并发 ⇒ 红 |
| **Sr9** | 零新增顶层键（十一键）／零新依赖（8 条）／既有 `M4` 判据族全绿 | 加顶层键 / 改 claim ⇒ 红 |
| **Sr10** | 每份撤销依据**按 rid 可取回**：N 条各自 `previous` 与还原依据在场；claim 只删自己那条 | 共用一份 / 张冠李戴 ⇒ 红 |
| **Sr11 ★（会诊 #101 [1]-① 折入）** | **授权路径分开**：协调者能成功准备 worker（逐角色不走现任门）；**非现任协调者发起整批 ⇒ 具名拒绝**；**单角色 `prepare` 的现任门一字不动**（非现任对单角色仍拒） | 把现任门放宽到单角色路径 / 非协调者也能批量 ⇒ 红 |
| **Sr12 ★（会诊 #101 [1]-③ 折入）** | **写前重读**：确认框返回后 roster/写策略若已变 ⇒ **整批中止、零写入**（`policy.update` 零次、`agents.create` 零次） | 用预热 view 覆盖 ⇒ 红 |

★ **修复前必红**：Sr1/Sr2/Sr3/Sr4/Sr5/Sr6/Sr7/Sr8 打在旧实现上必红（旧实现没有批量动词）；Sr9/Sr10 属**回归锁**（修复前绿，如实标）。

## 五、明确的非目标（本批不做）

1. **不做 agent-team 档的 Lead 更换**（那是 `set-mode` 的地盘）。
2. **不做「一把换完」**：Phase B 仍逐个本人 claim，批量只到 Phase A。
3. **不做混合批次**：v1 只收**全 auto**（插件自建继任者）或**全显式 id** 二选一，混合态失败面不值得首版背。
4. **不改交接文档格式**（五个硬节不变）、**不改 claim 的信任迁移语义**、**不改令牌类型**。
5. **不动黑板 / 台账 / 归档**（那是 A-4 批 T）。
6. **不新增顶层键**、不新增工具注册（**扩既有 `team_link_rotate` 的 action**）。
7. **不自动归档 / 不自动清理**任何 pending 或撤销依据（过期清扫仍是既有语义）。
