# 需求档：换届映射的歧义/缺失/去重回执（批 Y，2026-11-05）

> 状态：**已实施（批 Y，2026-11-05）** · 关联设计档：`docs/2026-11-05-rotation-mapping-receipt-design.md`
> 由来：批 X 交付代码评审的两条 Deferred（覆盖缺口 X7/X8 + 映射撞车回执不可见），台账 t-18。

## 一、背景

批 X 给 `claim` 的确认框加了「框后复读 + 按对端映射」。三条边界只有实现、没有被判据咬住，其中一条连回执都看不到：

1. **歧义**：一个旧会话同时出现在**两个角色**的版本史里 —— `mapRotationSelection` 会跳过（不猜），但没有任何断言钉住这个行为。
2. **映射目标不在候选**：对端已换届、但复读后的候选里没有与它相关的通道 —— 会跳过并写原因，同样没有断言。
3. **映射撞车**：用户既勾了对端的旧会话、又直接勾了它的**新现任** ⇒ 两条选择映射到同一个目标，代码走**静默 `continue`**：行为正确（不建重复通道），但回执里看不出这条被去重了。

## 二、目标

- 三条分支各自被一条**纯函数判据**钉住（`mapRotationSelection` 直接可测，不需要 store 夹具）。
- 映射撞车的去重**进回执**（`skipped` 行），用户能读到「这条被去重了」。
- **不改任何既有行为**：三条分支的「建不建通道」结论逐字不变，只补回执与判据。

## 三、用户故事

- **US-Y1** 作为用户，我勾了一个归属有歧义的对端时，回执里能看到「归属有歧义，跳过（不猜）」，而不是默默消失。
- **US-Y2** 作为用户，我勾的对端在确认框期间换届且新现任那边没有对应通道时，回执里能看到跳过原因。
- **US-Y3** 作为用户，我同时勾了旧会话与新现任时，回执里能看到「与另一条勾选映射到同一新现任（去重）」。

## 四、非功能标准

- 零 schema 变更、零新工具、零新持久状态。
- 既有 1803 条判据全绿（本批只加 3 条纯函数判据，总数 **1806 = 1803 + 3**）。
- 纯函数可测：`mapRotationSelection` 增补 `export`（与 `planRotationMigration` / `applyRotationTrust` 同一模式），判据直接调用它。
- 用户当前禁跑全量套件 ⇒ 本批先给「定向脚本」证据，套件红/绿待用户放开后补跑（如实登记）。
