### 附：B-2 的一次性救回记录（真机，2026-10-12 15:18）

**现象**：`team-link-mal-analyze-1011-coordinator-2345e3ad` 向一个**已换届**的会话发消息，接收方对话框被点了【屏蔽】⇒ 该会话**所有**跨会话消息被拒。

**根因（逐行核实）**：`~/.dsh/team-link/policy.json` 的 `policy.blockedSenders` 是**一张全局名单**（`lib/index.js:1020` 默认值 / `:1150` schema / `:1200` 归一化），
屏蔽写入后**没有任何回退路径**（全库 grep `blockedSenders` 只见迁移拷贝 `:2037` / `:2305`）；而 store **每进程只读一次**（`:1659` / `:2503`）⇒ 改文件必须重启。

**救回操作（父侧执行，可复核）**：

1. 备份 `policy.json` → `policy.json.bak-2026-10-12T07-18-40-401Z`；
2. 用脚本（**Node 直写 UTF-8 无 BOM**，只动 `blockedSenders` 一个键）把它置空：`["team-link-…-2345e3ad"]` → `[]`；
3. **写后回读**：`JSON.parse` 通过 · `teams` / `watchdogs` 逐字节一致 · BOM=false；
4. 用户重启 DSH ⇒ 复核：`blockedSenders` 仍为空、`savedAt` 未变（插件没把旧值写回去）⇒ **解除生效**。

★ **时序教训**：插件下一次写策略文件时会把**内存那份整份写回** ⇒ 手改之后必须**尽快重启**，否则改动会被覆盖。
